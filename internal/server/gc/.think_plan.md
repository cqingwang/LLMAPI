# 请求记录清理改造计划

## 根因

系统设置中的“立即清理”调用的是按保留天数执行的异步 GC。现有 `cleanupRequests` 在天数小于等于 0 时直接返回，因此该入口不能表达“删除全部请求记录”，且近期请求不会被删除。

## 方案

新增独立的 `clearAllRequestRecords` GraphQL mutation：由 GC Worker 分批删除全部请求执行记录、请求关联的用量日志和请求记录，并在删除数据库记录前清理非数据库存储中的请求/响应对象。该操作不复用保留策略，也不受保留 Trace 规则影响。

前端在存储策略卡片中保留原有按策略清理入口，增加独立的危险操作确认按钮；成功后刷新请求、执行记录和用量日志相关查询缓存。

## 验证

增加 GC Worker 回归测试，验证请求、执行和用量日志全部删除；执行定向 Go 测试、前端构建和 `git diff --check`。
