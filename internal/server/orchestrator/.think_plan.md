# Playground 渠道模型选择与请求取消修复计划

## 根因（2026-09-05）

- Playground 前端使用 GraphQL 的 `allModelEntries` 展示模型，该列表包含模型映射、前缀和归一化后的请求模型。
- 原指定渠道选择器为兼容渠道测试的隐藏原始模型场景，只使用 `GetDirectModelEntries`，导致 Playground 展示的请求模型在后端被判定为“不支持”。
- 指定渠道模型不支持错误未包装 `biz.ErrInvalidModel`，Playground 因而将可预期的输入错误返回为 500。
- 客户端取消请求时，Playground 将 `context.Canceled` 当作普通服务错误处理，产生误导性的 500 访问日志。

## 修复边界

- 保留原 `NewSpecifiedChannelSelector` 的直连模型行为，新增面向用户模型列表的选择器供 Playground 使用。
- 用户模型列表选择器使用与 GraphQL 展示一致的 `GetModelEntries`。
- 模型不支持错误统一包装 `biz.ErrInvalidModel`，由 Playground 返回 400。
- 请求读取或处理阶段检测到取消/超时后直接结束，不写入 500 响应；真正业务错误仍按原错误策略返回。

## 回归验证

- 映射模型选择测试验证 `deepseek-v4-flash` 可解析到渠道实际模型。
- 不支持模型测试验证错误可被 `errors.Is(err, biz.ErrInvalidModel)` 识别。
- Playground 请求取消测试验证取消上下文或取消错误不会被当作普通错误。
- 执行 `go test ./internal/server/api ./internal/server/orchestrator ./internal/server/gc ./internal/server/backup -count=1` 与 `git diff --check`。
